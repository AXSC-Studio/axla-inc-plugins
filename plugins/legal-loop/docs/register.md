# 台帳と置き場所：契約ループの仕組み

契約書を回すループ（[specs/legal-001-run-contract-loop.md](../specs/legal-001-run-contract-loop.md)）のうち、git に置くもの。データは利用側のリポジトリの `loop/legal/` に置く（Axla なら axla-inc/loop/legal/）。契約の実物（原本・版ごとの gdoc と .docx・Loop Log）は Drive の契約フォルダに置く。

| 場所 | 中身 |
|---|---|
| `loop/legal/LEGAL.md`（利用側） | Legal の決まり（開発の CLAUDE.md と同じ立ち位置）。版は世代 X。NDA は中の章。子セッションは毎回全文を読む（RAG ではない） |
| `prompts/reviewer-prompts.md`（このプラグイン） | 内側のループの検証役への指示文（SemVer） |
| `loop/legal/register.csv`（利用側） | 台帳。全契約を1行ずつ |
| `loop/legal/contracts/<契約 ID>/`（利用側） | 契約ごとの記録（`loop-log.md`・`Redline Data.json`・スクショなど）。**git に入れない**（.gitignore。契約の本文が入るため） |

## register.csv

| 列 | 中身 |
|---|---|
| id | 契約 ID。Drive の契約フォルダ名の頭（`yymmdd_種類`）＋`_`＋連番（例：`260101_NDA_1`） |
| 種類 | NDA など |
| 入口 | A＝受信（相手の雛形で始めた）／B＝発信（Axla の雛形で始めた） |
| 受領日 | 雛形を受け取った日（入口 B なら始めた日） |
| 状態 | G1 待ち／送付待ち／相手の返事待ち／署名待ち／Signed など。補足は（）で書く |
| 現在の版 | 契約書の版 vX.Y.Z（下の「版の数え方」）。Final・Signed になったらそう書く |
| 検証の周回 | 内側のループを回した数の通算（＝いまの Z） |
| 相手との往復 | Axla が送った回数 |
| 人が触った回数 | 下の数え方 |
| 署名日 | Signed の日 |
| 署名までの日数 | 受領日から署名日まで |
| LEGAL.md 世代 | その契約で読んだ LEGAL.md の世代（＝ X） |

- **版の数え方（vX.Y.Z）**：X＝外側ループが回った数（LEGAL.md の世代。Signed のあと学びを PR でマージしたら +1）、Y＝相手との境目をまたいだ回数（1＝相手の原本、2＝Axla の直し、3＝相手の返事 …）、Z＝その契約の内側ループの通算周回（Y が上がってもリセットしない）。ファイル名にも出し、そのファイルを受け取った・送ったときの数字で固定する（例：`F_v0.1.0_<相手> Original.docx`、`F_v0.2.7_Axla Comments.docx`、次に相手から来るのは `F_v0.3.7_…`）。
- **人が触った回数**：G1（事業の判断）・G2（署名）・送信・人の手作業（添付を付ける、スクショを撮る、パスワード付きの添付を開くなど）を、それぞれ1回と数える。ループがどれだけ人の手を借りたかを見るための数で、少ないほど回っている。
- **ID と Drive の結びつけ**：Drive の契約フォルダ名 `yymmdd_<契約名>_<相手> ✕ Axla Inc.` の頭の日付と種類が、id の頭と同じになる。同じ日に同じ種類が2件あれば、連番で分ける。どのフォルダが何番かは、そのフォルダの `loop/legal/contracts/<契約 ID>/loop-log.md` のいちばん上に id を書いて結ぶ。
- **相手の名前を書かない理由**：NDA では、契約を結ぶこと（検討していること）そのものが機密情報に入ることが多い。git は Drive より広く共有されるので、相手の社名・担当者・条文は書かない。相手が分かるのは Drive の契約フォルダだけにする。
- **更新するとき**：中間ループの各段階の終わり（直しを送る準備ができた・相手の返事が来た・G1 で決まった など）と、Signed のとき。更新はコミットとして残す（いつ何が変わったかが履歴になる）。
