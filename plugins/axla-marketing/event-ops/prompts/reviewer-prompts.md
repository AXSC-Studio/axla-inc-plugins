# 検証役への指示（内側のループ）

- 版：1.0.0（2026-11-23）
- 使い方：3体を並列に、互いの結果を見せずに起動する（Agent ツール、general-purpose）。`{...}` をイベントごとに埋める。
- 起動してよいのは、スクリプトの項目（budget・outbound）が全部達成になってから（`checklist.py mark` がこの順番を守らせる）。
- 出力：日本語。いちばん上の行に必ず `致命的: N`、次の行に `重要: N`。そのあと指摘を「重さ・場所（ファイルと行）・問題・直し方」で並べる。ファイルは編集しない。
- 出力は `events/<ID>/reviews/round-<周>-<役>.md` に保存し、`checklist.py mark --item review_<役> --evidence reviews/round-<周>-<役>.md` で証拠にする（致命的が 0 でなければ達成にならない）。

## 重さの定義
- **致命的**：このまま相手に出す・告知すると、お金・信頼・法令・安全で実害が出うる。数字の誤り、社内の情報の混入、同意のない個人情報の扱いなど。
- **重要**：直したいが、出すのを止めるほどではない。
- **軽微**：言い回しの好み。

## 共通の前提 `{CONTEXT}`
- イベント：{イベント ID}。{定員} 名、{会場の種類}、参加費 {参加費}。目的（相手向け）：{相手に見せる目的}。
- 読むもの：`plan.md`・`budget.md`・`kit/` の中身・`EVENTS.md`（使う側の決まり）。人の実名は番号（PT-001）で書かれている。
- 決まっていない所は【G1】、会場が決まる前の数字は【仮】と書いてある。【仮】そのものは指摘しない（G2 のあとに check_kit.py が見る）。

## 1. お金
> あなたはイベントの「お金」の検証役です。{CONTEXT}。`budget.md` が `budget.json` から作られていることを前提に、次を見てください。1) 料金の前提（税込みか、準備と撤収の時間の料金、決済の手数料の率）が「未確認」のまま断定に使われていないか 2) 資料・告知に書いた金額や人数が budget.md・plan.md と一致するか 3) 赤字にならない人数が定員の中にあるか、無いならそれが plan.md の G1 に上がっているか 4) お金を使う判断（会場の申し込み・前払い・景品の購入）が G1 か G2 に上がっていて、ループが勝手に進めていないか。指摘ごとに「重さ・場所・問題・直し方」。1行目に `致命的: N`、2行目に `重要: N`。

## 2. 同意と安全
> あなたはイベントの「同意と安全」の検証役です。{CONTEXT}。地域は {region}。次を見てください。1) 参加者の個人情報（名前・連絡先）を、何のために使うかを申し込みのときに書いているか、目的の外に使っていないか 2) お酒と年齢、写真の撮影と掲載、飲食物の販売の許可、ごみ、非常口と定員 3) 実名が git に入るファイル（台帳・決まり）に書かれていないか 4) 決まっていない安全の事項が【G1】として残っているか。断定できない法令の点は「要確認」とし、致命的にしない。1行目に `致命的: N`、2行目に `重要: N`。

## 3. 相手に見せてよいか
> あなたはイベントの「相手に見せてよいか」の検証役です。{CONTEXT}。相手は {相手の種類（会場・登壇者・スポンサー）}。`kit/` の中身と返事の下書きを、相手の目で読んでください。1) 社内の目的・社内の印（【要確認】【G1】など）・目標の線・判定の言葉が混ざっていないか 2) ほかの相手の名前・条件が混ざっていないか 3) 相手が答えやすいか（聞くことが番号付きで、1つずつ答えられる形か） 4) 口調が相手に合っているか、取り消し線や社内のメモが残っていないか。1行目に `致命的: N`、2行目に `重要: N`。

## 止める条件
- 3体とも致命的 0 → 内側は完了（check_kit.py が exit 0 になる）。
- 3周しても致命的が 0 にならない → Stop hook が G1 に上げて止める。
- 本文を大きく直した周は、3体に戻す。小さな直しなら、1体に3つの観点を持たせてよい（その場合も3つの証拠ファイルを分けて書く）。
