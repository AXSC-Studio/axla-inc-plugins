# 001 · define event loop（イベントを回す三層のループ）

> 自分で会場を借りて開く数十人のイベントを、「立ち上げ（告知と資料一式）→ 相手とのやりとり（送る・直す・開催・お礼）→ 次回への学び」まで回すループの全体の決まり。event-ops は axla-marketing の機能の1つ（`plugins/axla-marketing/event-ops/`）。配るのはループの7つ道具の部品・ひな形・差し込み口で、ループそのものは使う人の環境で組み上がって回る

**実装**: `plugins/axla-marketing/event-ops/` 全体（specs/002〜009 がこの決まりの部品）。呼び方は `/axla-marketing:<スキル名>`
**起源**: 最初の実例（定員 48 の有料会場イベント）と、2026-11-23 の設計ディベート3回（4案＋反論2人／4案＋反論8人＋認識の反証／世界のベンチマーク4観点＋告知サービスの裏取り＋最終案の反証2人）
**ステータス**: L1（spec 起票・Human Judge 確認待ち）

---

## 1. Specify

### 何をするか
- イベント1件を、三層のループで回す。
  - **内側**：告知の下書き（アイキャッチを含む）と資料一式（概要・スポンサー向け・会場レイアウト）を作り、チェックリストが全部「達成」になるまで直す。
  - **中間**：一式を会場・登壇者・スポンサーに送り、返事とフィードバックで内側を呼び直す。会場を確定し、告知を公開し、開催し、撤収し、来場者にお礼とフォローアップを送る。
  - **外側**：封じた線と結果を照らし、学びを使う人の決まり（EVENTS.md）とひな形（templates/）の直しとして PR にする。次のイベントの立ち上げは、それを読んで始まる。
- 送信・公開・支払い・契約は人が押す。ループは、その手前で物理的に止まる（002）。

### 物差し（北極星）
- **1件あたりの人の手の時間**と、**人の判断の数**。前のイベントより減ったときだけ、ループが良くなったと言う。
- 結果の数（来場・その後の面談など、使う人が封じた線）を合わせて見る。
- 配るかどうかは、`claude plugin eval` で「プラグインあり」と「なし」の差がプラスであること。
- 定義はこの spec、実数は使う人の `runs.jsonl` と `register.csv` に置く。

### 受け入れ条件
- [ ] 三層それぞれに、7つ道具（下の表）が会話の外（ファイル・スクリプト・hook・ルーティン）にある
- [ ] 内側の完了は `checklist.json` の全項目が「達成」で、各項目に証拠のパスがある。作った役は検証器にならない
- [ ] 告知は非公開の下書きまで。公開・一斉メッセージ・招待・送信・支払いは、hook が止めるか、人の承認の記録がある
- [ ] 外側の PR がマージされた後、次のイベントの立ち上げが、そのコミットの EVENTS.md を読んだことを記録に書く
- [ ] `event-ops/` のフォルダに、特定の会社・人・相手の名前と、特定の国だけの決まりが 0件（CI の `check-neutral` が通る）
- [ ] 告知サービス・メール・資料・CRM を1つも接続しなくても（`manual`）、1周目が最後まで回る

## 2. Plan 外部設計

### 三層

| 層 | 1周 | 起動トリガー | 検証器（証拠） | 終了条件（達成／人へ／予算切れ） | 周期 |
|---|---|---|---|---|---|
| **内側** | 一式を作る → 判定 → 直す | `plan-event` を呼ぶ／中間からの「直して」／途中から取り込む（adopt） | `checklist.json`（全項目「未達」から始め、証拠のパスで「達成」）＋ `check_kit.py`・`recalc_budget.py`・`check_outbound.py` が exit 0 → 検証役3体 | 達成＝致命的 0件／人へ＝3周で G1／予算切れ＝`max_rounds` | 分 |
| **中間** | 相手との1往復 | 返事と送信済みの見張り（006）・朝の予備起動・`manual` の人が入れる「送った／電話で決まった」 | `update_partners.py`（送った事実・受け取った返事・確定の記録を突き合わせて状態を進める） | 達成＝撤収の確認・精算・お礼の送信の3つがそろう／人へ＝G1・G2・返事待ちが規定日数を超える／予算切れ＝開催日＋精算の日数 | 日 |
| **外側** | 線と結果の照合 → 学び → PR | 開催日＋N日で自動で「終了」を立てる | `judge_lines.py`（封じた線と件数）＋前回からの人の手の差＋人のマージ | 達成＝マージ／人へ＝差が減らなければ差し戻し | イベントごと |

- 内が回り切ると外が1歩進む：内側の合格 → まとめ承認（送信）→ 中間が1歩 → 撤収・お礼 → 「終了」 → 外側 → EVENTS.md と templates/ → 次の内側。
- プラグイン本体へ戻す輪は層にしない。使う人が件数だけを Issue のテンプレートで本体へ報告する口を置く（009）。

### 7つ道具（The 7 Loop Primitives）

どのループも、次の7つが会話の外（ファイル・スクリプト・hook・ルーティン）にそろったときだけ、人がプロンプトを打たずに回る。

| # | 道具 | English | 内側 | 中間 | 外側 |
|---|---|---|---|---|---|
| 1 | 起動トリガー | Trigger | スキル・中間からの呼び直し・adopt | 返事と送信済みの見張り・朝の予備起動・manual の入力 | 開催日＋N日の「終了」の自動の印 |
| 2 | 実行境界 | Sandbox | 送信・支払いの道具を止める hook・`check_outbound.py`。ルーティンは読む道具だけ | 承認にない宛先・凍結した版と違う版への送信を止める | `check-neutral`（CI）・`check_pii`（コミット前） |
| 3 | 検証器 | Verifier | `checklist.json`＋3つのスクリプト（exit code）→ 検証役3体 | `update_partners.py`・`check_kit.py`（【仮】の残り） | `judge_lines.py`（封じた線と件数）＋前回からの人の手の差 |
| 4 | 終了条件 | Exit Criteria | 達成＝致命的 0件／人へ＝3周で G1 | 達成＝撤収の確認・精算・お礼の送信／人へ＝G1・G2・返事待ちの超過 | 達成＝PR のマージ／人の手が減らなければ差し戻し |
| 5 | 予算上限 | Budget Cap | `max_rounds`（初期値 3） | 開催日＋`settle_days` | イベント1件に1回 |
| 6 | 状態ストア | State Store | `checklist.json`・`event-log.md` | `partners.csv`・`sent/`・`approvals/` | `EVENTS.md`・`templates/`・`runs.jsonl` |
| 7 | 承認ゲート | Human Gate (HITL) | G1（3周で止まったとき・既定値の外） | 送信（まとめ承認）・G2（確定） | PR のマージ |

- 表に入れない3つの働きは、event-ops では次のものが担う。**次の一手を選ぶ**＝`checklist.json` の未達の項目と、記録の先頭「次の一手」。**手を動かす**＝4つのスキル。**続きから再開する**＝SessionStart hook が記録の先頭を読み込む。
- 1周＝1行を `runs.jsonl` に書く（層・道具・結果・fail_code・人の手の分数・判断の数）。
- 同じ fail_code が2回出たら、実行境界（Sandbox）か使う人の決まりに上げる。

### 4つのエンジニアリング（入れ子）

ループ ⊃ ハーネス ⊃ コンテキスト ⊃ プロンプト。

- **プロンプト**（9本）：SKILL.md 4本、`prompts/reviewer-prompts.md` の検証役3本（お金／同意と安全／相手に見せてよいか。返すのは場所と根拠だけ）、`prompts/routine-triage.md`（スレッド ID と要約だけ）、`prompts/routine-morning.md`（返事待ちと G1 の件数）。
- **コンテキスト**：

| 置き場 | 中身 | 書き手 |
|---|---|---|
| axla-marketing の `event-ops/` | specs・skills・prompts・scripts・hooks・ひな形・adapters | 作り手（PR） |
| 使う人の git `loop/marketing/event-ops/` | `EVENTS.md`・`templates/`（人がマージ）、`config.json`（人）、`register.csv`・`partners.csv`・`runs.jsonl`（スクリプトだけ。実名なし） | 人・スクリプト |
| 使う人の git の外 `loop/marketing/event-ops/events/<ID>/` | `event-log.md`・`plan.md`・`checklist.json`・`sent/`・`approvals/`・`names.local` | スキル・スクリプト |
| 外部 | 告知サービス・メール・資料の置き場・CRM・仮説の線の文書（`lines_source`） | 人（ループは読むだけ。書くのは承認の後） |

- **ハーネス**：

```
メール/告知サービス → adapter → ルーティン（読む道具だけ）→ 知らせ
→ スキル → scripts（exit code が判定）→ hooks（実行境界）
→ 承認 ID つきの下書き → 人が送る/公開する → 見張りが送信済みを記録 → runs.jsonl
```

- **ループ**：上の「内が回り切ると外が1歩進む」。

### スキル（4つ・段階ごと）

| スキル | 層 | 仕事 | spec |
|---|---|---|---|
| `plan-event` | 内側 | 計画・収支・告知の下書き・アイキャッチ・資料一式を作り、checklist が全部達成になるまで直す。途中から取り込む（adopt） | 003・004 |
| `coordinate-partners` | 中間 | 返事を読み、凍結した版と承認 ID つきの返事の下書きを作り、内側を呼び直す | 005・006 |
| `measure-event` | 中間 | 当日の段取り表・撤収の確認・件数・来場者へのお礼とフォローアップの下書き | 007 |
| `review-event` | 外側 | 線と件数を照らし、学びを EVENTS.md と templates/ の PR の案にする | 008 |

### 人間ゲート（3つ）

| 呼び方 | 人がすること |
|---|---|
| **G1**（事業の判断） | 開催日・定員・参加費・線を封じる・相手を選ぶ・お金を使う・既定値の外の判断 |
| **送信**（まとめ承認） | 「凍結した版の URL＋版のハッシュ＋宛先の一覧」を1回承認する（`approvals/A-NNN.json`）。見た目の確認もここ。告知の公開・一斉メッセージ・招待もここ |
| **G2**（確定） | 会場の申し込み・支払い・契約 |

- 決まりの中の項目（時間割・搬入の順・係・言い回し）はループが既定値で決め、記録に書く。人はあとから直せる。

### 差し込み口（汎用）

| 種類 | 既定 | 用意する adapter |
|---|---|---|
| `~~events`（告知） | manual（貼る文面と画像を作る） | luma（公式 MCP） |
| `~~docs`（資料） | manual（Markdown） | artifact |
| `~~email` | manual（貼る文面＋「送った」を手で入れる） | gmail |
| `~~crm` | なし（番号だけ） | 使う人が足す |
| `~~metrics` | 名簿の CSV を数えて捨てる | luma |

使う人が最初に設定するもの：`locale`・`currency`・`tax_rate`・`region`・`approvers`（一人なら self）・`kit`（資料一式の中身）・`lines_source`・各 adapter。

## 3. Plan 内部設計・単体テスト条件

- 判定はスクリプトの終了コードを正とする（0＝合格、1＝不合格、2＝実行境界で止めた）。LLM の検証役は、スクリプトが全部 0 の後にだけ動く。
- 各スクリプトには、`tests/` に合格・不合格の例を1つずつ置く（CI で回す）。
- 告知サービスは、まず公式 MCP でつなぐ（最初の版）。API キーが要る経路は使わない。

## Non-goals（最初の版）

- 支払い・会場の申し込み・契約の操作（G2 は人）
- outlook などほかのメールの adapter（manual で回る）
- 外側の「学びの質」の機械判定、NPS の計算
- 使う人の記録を自動でどこかへ push すること（朝の知らせは、手元とメールの件数だけで出す）
- オンラインだけのイベント、数百人を超えるイベント
